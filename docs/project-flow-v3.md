# 项目流程 V3 开发入口

2026-10-28 起，主导航“项目流程”进入 V3；沿用品牌紫 v4，在独立 V2 备份的基础上迭代。此版本号只针对项目流程页面，其他模块不因此重新编号。

## 入口与源码

- V3：`/#project-flow-v3`，开发源码为 `apps/web/src/features/research-flow/`，样式为 `apps/web/src/styles/research-flow.css`，主导航内部标识为 `流程V3`。
- V2：回收站 → **工作流程V2**，地址 `/archives/workflow-v2/index.html#project-flow-v2`。完整运行快照位于 `apps/web/public/archives/workflow-v2/`，包含入口、脚本、样式、模型与资源，不依赖当前活动版本的脚本或样式。
- 根地址旧书签 `/#project-flow-v2` / `/#workflow-v2` 自动打开 V2 备份。旧版文档式项目流程、项目实验仍保留原有备用入口。
- V2 中主导航“项目流程”可返回 V3；V2 备用入口保持选中并自动展开回收站。

## 冻结及数据边界

V2 快照不再作为后续开发目录。`manifest.json` 记录 60 个运行文件的 SHA-256；版本测试校验其完整性。V3 的后续界面、交互与数据修改不能通过共享运行文件影响 V2。

V3 首次加载前，将已有 `synmat-` 本机记录复制一次到 `workflow-v2::` 命名空间；V2 只读写该副本。V3 保留原有本机记录继续开发。两者后续写入、删除互不影响，不清除原数据。旧版整个产品 V1 的独立版本目录保持冻结。

首次复制发生在当前浏览器第一次加载新版入口时，非服务器备份；未在本机持久化的会话上传内容不包含在此复制中。真实 AI、后端和服务端备份均未接入。

## 验证

运行 `node scripts/check.mjs`、`node --test scripts/*.test.mjs` 和 `node scripts/build.mjs`。构建将冻结资源一起复制到 dist，开发服务无需修改即可提供两版本入口。


## 三层流程布局（2026-10-28）

任务视图的顶部缩略导航展示从市场分析至量产的完整工作包阶段链及各阶段的依赖顺序，可横向滚动，当前阶段进入视区中央；组间用与节点垂直居中的 `|` 分隔。当前阶段名称和节点更醒目，其他阶段保持可点击跳转。导航默认无底色，悬停或键盘聚焦才显示半透明毛玻璃。阶段、任务视图的输入/输出虚拟节点压缩为仅显示名称的紫色胶囊；单独选中节点只高亮对应文件侧栏，不弹出选区快捷菜单。

- 移除原项目名称与四阶段状态横条，保留全局面包屑。Supervisor Agent 固定在内容区左侧，上下撑满；切换层级保留对话、引用和未发送草稿。
- 第一层“全局”：四个项目阶段以节点及推进连线展示；研发、量产在同一画布展开有序子阶段。市场分析与项目立项没有额外子阶段，双击直接查看工作包。
- 第二层“阶段”：双击子阶段进入，复用原工作包依赖、路线筛选、编辑、文件与右键详情。双击工作包继续下钻。
- 第三层“任务”：读取原工作台保存的待办、内部依赖、文件；计算模拟读取现有计算节点拓扑。没有真实依赖的任务按并行分支连接至工作包输入和输出，不写入实际依赖或完成状态。本轮内部视图为只读投影，需执行、修改或继续对话时使用“打开工作台”。
- 深层画布左右窄栏分别承接上游输入、面向下游交付，固定 76px，不展开，仅显示前后项名称及文件图标，悬停图标显示完整文件名（未关联项同时提示为预期交付）；工作包层按相邻子阶段展示，内部层按相邻工作包展示。S2 左侧为相容验证，右侧为交付给因子筛选的文件。
- 文件优先使用工作包明确登记的交付引用，否则显示已有资产与工作区文档；未关联时展示“预期”交付要求，不能当作已有成果。所有视图复用本机记录，三层视图本身不执行任务、不自动放行阶段。
- 新增 `hierarchy-model.js` / `hierarchy-view.js` 和 `project-flow-v3.css`，修改仅作用于活动 V3，冻结 V2 文件不变。

### 视图切换与窄栏精简

顶部移除通栏背景、重复路径、数量与编号；“全局 / 阶段 / 任务”选择器位于画布右上角，控制查看深度。当前位置使用全局面包屑及 Agent 上下文说明。阶段视图保留技术路线筛选，移至画布底部工具附近；任务视图的打开工作台入口位于右下方工具附近。

视图切换使用约 170ms 的退出缩放及 330ms 的进入缩放，放大下钻、缩小返回；只作用于画布，Agent 和工具保持固定。减少动态效果偏好下直接切换；动画过程中防止重复导航。阶段视图进入任务时优先使用选中的工作包，其次保留上次工作包或当前进行中的工作包。

两侧无展开操作、冗余文件数量、说明段落或邻阶段跳转按钮；文件列表只显示图标并保留键盘可访问名称、悬停完整文件名及已有预览入口。图标浅紫实底表示已关联文件，虚线边框表示尚未关联的预期交付。


### 全局阶段分组及相邻阶段切换

全局视图按项目推进顺序展示立项、研发阶段1、研发阶段2、量产。研发阶段1包含现有六个子阶段，末尾的“客户准入”同时承担本轮小试反馈收集，向下一轮 SOP 规划提供输入；不在研发阶段外另设小试反馈节点。以后每轮研发也由本轮客户准入收集反馈。研发阶段2是等待上一轮反馈和新 SOP 审批的待规划占位，不复制第一轮任务，也不表示第二轮已经执行。全局画布的研发阶段1标签和顶部缩略导航均可折叠或展开这六个子阶段，状态保存在本机，两处共用；折叠后以一张汇总卡代替六张卡，连线保持连续。阶段与任务视图的画布不受折叠影响。完整的多轮 SOP、客户反馈和阶段任务需要后续接入独立轮次数据；当前仍保持底层四阶段业务记录和原工作包依赖。全局进入时适应完整画布，可主动放大查看。

阶段视图的左右栏顶部为前/后阶段切换入口（固定宽度，不展开），前一阶段内容向右滑入、后一阶段内容向左滑入；支持跨项目阶段衔接。任务视图的左右栏按真实工作包依赖切换前/后工作包。两层入口均只显示方向图标，悬停或键盘聚焦时显示完整名称，首/末项禁用对应入口；文件图标点击仍只查看文件。

验证：92 项自动检查及构建通过；浏览器验证三组数量、跨阶段切换、起点禁用及返回下一阶段，未出现页面错误。

### 一体化项目工作流与虚拟边界

项目数据按市场分析 → 项目立项 → 研发六个子阶段 → 量产三个子阶段，组织为一张连续的有向工作流。四个项目主阶段、11 个可查看的阶段/子阶段各有虚拟“输入”和“输出”边界；阶段内每个工作包也有自己的“输入”和“输出”。前一阶段的输出连接后一阶段的输入，工作包真实依赖则连接上游包的输出与下游包的输入。全局、阶段和任务视图是这张大图的不同层级投影。

已有的真实任务连线保持原样。没有前置节点的工作包或内部任务从所属输入节点分叉；来源流程中没有后置节点的内容仍汇入所属输出节点，但用户新建且未连接下游的节点保留为敞口终态，不自动补到输出。并行内容不会被临时排成串行。空阶段/空工作包由输入直连输出。虚拟边界和补充连线只在 V3 投影与整合数据模型中生成，不写入原始草稿、本机工作台依赖或完成状态，也不能在画布中删除、编辑。已完成节点只允许作为新连线起点，不能接收新连线；工作包和文件仍按原有操作管理。

### 顶部阶段缩略导航

画布顶部使用紧凑的横向流程缩略图。全局、阶段视图显示“立项 → 研发 → 量产”三个分组下的 11 个阶段/子阶段图标，当前阶段以品牌紫标记，图标角落保留完成/进行中/待开始状态点。任务视图显示当前子阶段的工作包流程及真实并行关系。常态只显示分组与小图标；鼠标邻近时局部放大，聚焦节点显示全名和状态，键盘也可用方向键遍历并显示同等提示。

点击全局缩略图节点定位该阶段；在阶段视图中切换对应阶段并保持原有左右滑动；任务视图中切换工作包。选择“全局 / 阶段 / 任务”仅改变下钻层级，缩略图不修改流程依赖、完成状态和文件。减少动态效果偏好下保留信息提示并关闭过渡。

仅流程缩略图容器使用半透明毛玻璃，画布保持原有背景；缩略节点按适当固定间距紧凑排列，不随容器宽度分散铺满。选择器保持右上角。两侧交付栏收窄至 56px（窄屏 52px），方向箭头统一用居中的 SVG；交付栏从缩略图实际底边下方开始。任务视图两侧的切换依据当前工作包的前/后依赖；并行后继在侧栏中以当前显示的第一项为切换目标，其余仍可从顶部缩略图直接选择。

### 切换后的默认画布定位

每次进入 V3 或切换全局、阶段、任务视图及相邻阶段/工作包时，在顶部缩略导航与两侧交付栏布局完成后，以当前工作流全部节点和连线的边界执行“适应画布”。不再默认定位输入节点或沿用上一个视图的缩放位置；用户之后仍可自由缩放、平移，并用“当前任务”主动聚焦单点。适应缩放允许低于通常的编辑缩放下限，保证大流程先完整呈现。

顶部阶段缩略图和视图控制共用一条半透明毛玻璃浮层。缩略图延续紧凑节点与指针悬停放大，右侧以三个图标切换“全局 / 阶段 / 任务”，选中图标使用品牌紫实底，悬停与键盘聚焦显示文字提示；整条浮层只用一次边界和阴影，避免两块独立控件割裂。

浮层左侧固定放置“工作台 / 项目流程”一级视图切换，中部继续展示当前层级的缩略导航，右侧保留“全局 / 阶段 / 任务”深度切换。三个深度使用同一顺序和选中反馈，不再各自生成位置不同的入口。项目流程左侧同时复用工作台的项目内对话列表与 Agent 栏：列表可收起、悬停预览、切换项目/阶段/工作包对话，窄屏以全高浮层恢复，避免流程视图维护第二套对话状态。

共享 Agent 栏与无限画布独立挂载，Agent 标题结构变化不得阻断流程节点、连线及顶栏初始化。全局、阶段、任务三种视图都必须存在对应流程；如果保存的层级、阶段或工作包已经失效，入口自动清除失效选择并回退全局流程。

### 阶段视图的工作包创建与边界操作

阶段视图的新建菜单仅提供“创建工作包”，通过节点端口、选区或底部添加入口创建的都是工作包。分隔线下说明实验、审批等末级任务应进入工作包后创建。输入/输出虚拟节点保留极简标识，单独选中时不显示批量快捷菜单，并同步高亮对应侧栏文件。输入只从右侧发起连线，可连接现有工作包或在空白处创建工作包；输出只从左侧接收连线。左侧已有文件可拖到未完成工作包，保存为本地演示的文件引用连线，在线路信息中列出文件名。虚拟边界的提示说明上下游来源与交付，不改变原始工作包定义或完成状态。
