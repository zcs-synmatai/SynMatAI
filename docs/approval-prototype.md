# 项目管理与审批原型

项目概览增加“项目管理”，在此配置成员及项目负责人、Leader、上级、+2级别四个审批角色。主菜单增加“审批中心”，提供待我审批、我已处理、我发起的及演示身份切换。

## 配置

流程变更、工作流转、项目审批分别配置阶段、子阶段、工作包、任务四层规则；项目审批额外支持项目本身。工作流转区分启动、完成配置。勾选角色依次审批，同一人员合并；无勾选直接生效；必审角色未配置人员时提示补充。请求保存提交时的审批链，后续规则变化不影响已提交请求。

## 已接入的操作

- 工作台任务完成：按任务完成规则发起申请，通过后更新状态并继续下游。
- 项目立项：提示正式环境需要审批，可模拟通过并留记录。
- SOP确认：按流程变更的阶段规则提交，通过后生成研发阶段1。
- 工作流内任务创建、快速修改、删除：按任务变更规则提交。
- 工作包编辑和依赖变更：按工作包变更规则提交。

审批中心展示项目、申请人、操作及影响、申请说明、变更前后、审批链和意见；可以通过或驳回，驳回原因必填。详情提供只读流程预览和节点工作台入口，并可返回审批。

## 演示步骤

审批中心首次自动补充8条内置示例申请，关联“高导热凝胶开发示例”的真实节点：BLT要求变更、小试交付、中试启动、SOP规划、项目立项、供方资料审核、热学记录精简驳回及资格包驳回。默认身份林晓有3条待审、2条已处理、3条我发起的；切换王宁可演示SOP逐级审批。示例申请只更新审批记录，不改变研发节点进度。仅初始化一次，刷新不会重复添加或重置审批结果，用户自行发起的申请保持不变。

1. 项目概览 → 项目管理，确认角色人员。
2. 在流程变更的任务行勾选Leader，保存；创建一份演示申请。
3. 审批中心切换为张三，在待我审批中查看申请，预览流程并进入关联工作台。
4. 返回审批详情，通过或填写原因驳回。
5. 在工作流实际新建、修改任务，验证审批前后生效；工作台完成任务可按工作流转规则同样演示。

## 本轮边界

本地演示身份不代表真实权限；无服务端审批或组织通讯录。四层规则矩阵完整保留，阶段/子阶段的独立启动拦截、暂停/终止/结项及重开操作尚待对应业务操作接入。默认均不启用审批，以免改变现有演示推进方式。后续扩展应复用统一申请及处理模型。
