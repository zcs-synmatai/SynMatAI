# 新项目完整演示流程需求

## 目标

补充一条从项目列表、新建项目、立项调研到首个研发阶段及后续规划的完整演示流程。流程用于前端交互演示，项目、AI 对话、文档生成和流程生成均保存在本机，不代表已接入真实 AI、审批或后端服务。

## 项目列表与导航

- 新增“项目列表”作为全局入口，路由为 `/#projects`，位置高于项目概览、项目流程、任务工作台和项目资产。
- 项目列表默认保留“防刮擦涂层优化”示例项目，并展示用户在本机新建的项目。
- 项目卡片展示项目名称、负责人、当前阶段、当前任务、状态和最近更新时间；提供“项目工作台”和“项目流程”两个明确入口。
- 页面右上提供“新建项目”。第一版只收集项目名称、负责人和可选简介，不在创建表单中重复询问项目目的、约束和预期产出。
- 项目列表为空时展示简洁空态和新建入口；现有示例项目不可误删或被新建项目覆盖。
- 进入项目后，原有项目概览、项目流程、任务工作台和项目资产均读取当前项目；返回项目列表不会改变任务状态。

## 新建项目

1. 用户在项目列表点击“新建项目”，填写基本字段并确认。
2. 系统创建独立项目记录，设为当前项目，并初始化立项阶段状态。
3. 创建成功后直接进入该项目的技术调研工作台，AI 发出第一条基础信息询问。
4. 浏览器刷新或返回项目列表后，可分别进入该项目的当前任务工作台或项目流程。
5. 重复提交或页面恢复不得创建重复项目；创建失败时保留表单内容并给出明确提示。

## 演示流程

1. 创建项目后，默认进入“项目立项”阶段。
2. 立项阶段包含四个顺序节点：需求确认 → 技术调研 → 项目立项 → SOP 审批。
3. 初始状态为：需求确认已完成、技术调研进行中、项目立项和 SOP 审批待开始；页面自动进入技术调研工作台。
4. 此时研发阶段和量产阶段只展示阶段占位，不生成工作包和任务。
5. 用户依次手动确认技术调研完成、项目立项完成和 SOP 审批完成，后续节点按顺序激活。
6. SOP 审批完成后，生成首个研发阶段的工作包和任务。
7. 首个研发阶段进入“客户准入”工作包后，先收集用户反馈，再由用户完成“阶段任务确认”。
8. 阶段任务确认后，记录“下一研发阶段待规划”；只有后续明确决定启动时才生成新的研发阶段。新建项目不显示第二研发阶段占位。

## 技术调研交互

- 技术调研工作包包含“梳理技术路线与证据缺口”和“形成技术调研报告”两个并行 TODO，进入工作包时两项同时为进行中。用户在工作台分别确认当前 TODO；完成一项不弹出工作包完成确认，也不切换回流程画布。两项都完成后，系统再完成技术调研工作包并连续进入下一工作包。
- 技术调研对话开始时，AI 主动询问项目目的、约束条件、预期产出等基础信息，并允许用户补充或修改。
- 信息确认后生成 `项目基础信息.md`，作为技术调研的输入资产。
- 基础信息完成后，AI 自动演示技术调研过程，并生成 `技术调研报告.md`。
- 两份文档可在对话和项目资产中查看；生成文档不自动完成技术调研任务，仍由用户手动确认完成。

## 研发流程生成

- SOP 审批完成后，按预设模板生成首个研发阶段，不在审批前提前展示具体工作包或任务。
- 研发任务至少包含三种类型：文档、模拟计算、实验，并在卡片、列表和详情中使用一致的类型标识。
- “客户准入”包含“收集用户反馈”和“阶段任务确认”两个关键任务。
- 用户反馈作为下一阶段规划输入；完成“阶段任务确认”只进入待规划状态，不自动生成后续任务。
- 若未来明确启动新的研发阶段，新阶段应使用独立的工作包、任务、状态和资产，不复用上一阶段执行状态。

## 状态与数据要求

- 新增项目注册表，记录项目 ID、名称、负责人、简介、创建时间、更新时间、当前阶段、当前任务和最近页面。
- 所有流程进度、工作台、对话、文档、审批、反馈和研发轮次数据必须按项目 ID 隔离，切换项目不得串用数据。
- 现有未分项目保存的数据一次性归入“防刮擦涂层优化”示例项目，不清空原有本机演示数据。
- 关键节点只有“待开始、进行中、已完成”三种状态，且按前置关系依次激活。
- 自动生成文档、工作包和任务时应避免重复创建，刷新后保留当前演示进度。
- 用户反馈、两份调研文档和已生成研发阶段的数据均保留明确来源关系。
- 原型中的“自动调研”“自动生成”使用本地预设内容和短暂演示状态，不描述为生产能力。

## 页面衔接

- 项目列表使用现有品牌紫 v4 和紧凑研发工具风格，不另建新的视觉体系。
- 列表页不展示某个项目的阶段导航；选定项目后再显示项目级导航和项目名称。
- 顶部面包屑、侧栏项目身份、Supervisor Agent 标题、导出文件名和各页面标题均随当前项目更新，不再固定显示示例项目名称。
- 新项目尚未生成研发内容时，项目概览、项目流程和项目资产展示对应空态，不套用成熟示例项目的数据。
- 创建完成、文档生成、研发流程生成采用轻量状态反馈；不使用长时间不可跳过的演示动画。

## 实现建议

- 新增 `features/projects/`，包含项目注册表、当前项目上下文和项目列表页面。
- 项目注册表与项目业务数据分开保存；业务数据通过统一的项目存储适配层读取，避免各页面自行拼接存储键。
- 新增演示生命周期模型，统一处理项目初始化、节点激活、文档生成、首个研发阶段生成、客户反馈和后续阶段规划状态。
- `researchFlowData` 保留为研发模板；只有达到触发条件时才实例化为当前项目的工作包和任务。
- 技术调研工作台只保存问答和文档，不再维护与项目流程分离的独立完成状态。

## 推荐开发顺序

1. 建立项目注册表、当前项目上下文和按项目隔离的存储。
2. 完成项目列表、新建项目弹窗、项目切换和最近页面恢复。
3. 将现有示例项目迁入项目注册表，并替换页面中的固定项目名称。
4. 实现立项四节点和技术调研问答、文档生成。
5. 接通手动完成、SOP 审批和首个研发阶段生成。
6. 实现客户反馈、阶段任务确认和后续研发阶段待规划状态。
7. 补充空态、失败恢复、重复触发保护、响应式检查和完整回归测试。

## 验收场景

- 可从项目列表新建项目，创建后直接进入技术调研；返回列表后可以继续该项目。
- 两个项目的流程状态、对话和资产相互隔离，切换后名称和页面内容正确更新。
- 新建项目后可直接进入技术调研，研发和量产均无具体工作内容。
- 完成基础问答后可查看两份 Markdown 文档，并可手动完成技术调研。
- SOP 审批完成后只生成一个研发阶段，且包含文档、模拟计算、实验三类任务。
- 新建项目不显示第二研发阶段；客户准入完成阶段任务确认后只记录后续阶段待规划，不自动生成任务。
