# 项目实验与 ELN 原型

入口：左侧“实验”、`/#experiments`；单份实验的工作区使用 `/#experiments/EXP-012` 形式的稳定 ID 路由。

## 实验身份与来源边界

- 原型采用“一项明确条件一份实验单”，制备组、层批、样板、测量和修订另存。ID、14行演示数据及示例姓名/日期/观测是产品原型组织约定，并非源 SOP 指定的系统编号、实际执行事实或已批准路线。
- S1 放入 4 路线层液小试与 P0/P1 清漆空白热预算验证共 6 份；各层 3 组独立 100g 小试批，适用处保留 0/4/24h 观测。S2 放入 R1–R4 × P0/P1 共 8 份；同一路线两个前处理实验引用同 3 组制备，不重复算独立批。R3 每组分别登记 primer/top 层批。
- S2 计划的 96 块涂层专用板和 24 块受控匹配空白，共 120 板。24 块空白跨路线引用时保留唯一身份。板数不当作实验数、制备批数或已测数量。
- S3–S6 属研发后续计划，但路线、角点配方、最佳化学方案、氙灯程序/专用板或客户矩阵尚未确认，仅显示于“待明确实验计划”。S6 是准入评审；量产暂无已明确实验。后续计划只能根据人工补充的冻结条件及来源，先预览草稿、再确认纳入，不由 AI 自动选路线或补专业方案。
- 条件明确、方案确认、前置满足、实验执行是四条独立信息；抽取成功、文件上传和测量登记都不自动推进业务状态。

## 交互与数据

- 列表组合筛选阶段、子阶段、路线、前处理、状态、负责人和方案版本，支持实验/样品/制备批 ID 搜索、快速筛选、列设置、分页、本地摘要导出及责任分配。返回列表恢复筛选与滚动。量产有专门空状态和项目计划入口。
- 来源独立展示“项目阶段 / 研发子阶段 / 项目节点”，按项目阶段、子阶段、来源节点顺序组织，再按路线与前处理排列。S1四路线层液相容小试均来源T12，清漆空白来源T13；S2路线/处理条件实验来源T22，同时保留T21及T23–T25的关联。节点名称点击可进入对应任务工作台，筛选节点不创建实验副本。
- R1–R4统一使用“层液相容小试 · 路线名称”，其中“平衡单层”为R1路线名；R3仍按primer/top分别制备。旧默认名称兼容更新，保留实验ID、批次、测量及用户自定义名称。
- “从项目方案整理实验”展示固定来源与现有条件，保存待核对草稿，不复制已存在的 14 份实验或自动批准。手动登记允许关键字段暂缺，缺项显示在草稿中；负责人补齐后才能确认纳入列表，纳入时仍为“待方案确认”。
- ELN 展示固定输入资产版本、准备组及层批、专用样板、共享空白、测量记录和追加修订。原始记录不可覆盖；失败结果保留。测试人员可登记授权测量，实验主责可登记制备，项目负责人按演示授权确认方案及业务状态，只读成员只能浏览。身份切换仅是前端演示。
- 列表、ELN 与研究流程任务的记录引用同一 `synmat-experiments-v1` 本机数据。提交 ELN 测量时产生项目资产记录版本到 `synmat-project-assets-v1`，关联任务按同一 measurementId 查看。固定 SOP 与配方输入采用项目资产指定版本；真实源文件保持不变。
- 本机重置仅清除实验数据和由 ELN 生成的资产记录；不连接后端、模型、仪器或真实 ELN/LIMS。

## 核对

- `node scripts/check.mjs`、`node --test scripts/experiments.test.mjs`、`node scripts/build.mjs`。
- 浏览器验证研发 → S2 → R3 筛选为 P0/P1 两份；进入 R3 P1 ELN，测量提交后列表计数变化而业务状态仍为“待测试”。

实现：`apps/web/src/features/experiments/`、`apps/web/src/styles/experiments.css`。

## ELN 记录工作区

- ELN 默认“执行记录”，R3/P1 演示实验默认选择 B02。中央宽内容区与右侧可收起实验 Copilot 并排，项目主 Agent 不常驻；实验要求、执行记录、批次与样品、结果与测量、可见资产五个章节共享同一 experimentId。
- 草稿按实验、独立批和记录类型隔离保存于本机。自由笔记与制备/前处理/涂布固化/观察/异常的结构化字段并存，实际时间与录入时间分开；计划参数只在要求中展示。未保存离开/切批有处理提示，提交后修改需原因并保留历史作者、时间、原值及引用版本。
- R3 两层独立批号与各层质量/放行分开。计划样板用途固定，实收数量和清漆板批次可另行登记；匹配空白显示同区组、处理条件、用途和引用实验。未知实际量保持未登记。
- 本次新增的 B02 沸水专用板同板位置 A 初始光泽 90 GU 是独立的演示链基准，不来自 SOP，也不借用另一块破坏性试板。填写后测 83 得到 92.22%；78/白化/ISO2 可提交为失败事实。缺初始或分母为 0 显示无法计算；必要字段缺失只能保存草稿或带说明提交不完整交付，后者不计齐备。
- 表单按类型展示初始、沸水、擦伤、S1 相容观察、过程/其他及已明确 S5 实验的暴露字段。S3–S6 当前没有已确定实验或自动生成的专业程序；S5 专业程序/卡片仍需人工提供。
- CSV 支持文件或粘贴、列映射、单位/样板/重复检查、预览与取消。明确确认后仅形成对应批次的待核对草稿，仍需逐条补齐并提交；不自动换算、取均值或重复覆盖正式记录。
- SOP 阅读有真实章节目录、正文搜索高亮和指定版本定位。新资产版本只提示差异与记录影响；负责人确认后用于后续采用，既有测量与草稿保留自身采用版本。源 SOP 和标准公开摘要中的未决条件持续说明。
- 可见资产按来源访问和本实验关系筛选，ELN 附件沿用项目资产同一 ID/版本。已提交结果的附件有交付引用保护；二进制原件仅本次会话可下载。关联知识库复用概览的访问状态，仅取得目录元信息时不冒充读过正文。
- Copilot 对话按实验/批次隔离，以本地预设响应解释固定 SOP 和实际记录，依据卡可点击；撤销参考访问后不再引用。摘要先预览、确认保存草稿，聊天不能改变实测值、代提交或放行实验/项目阶段。
- 相关实现为 `eln-model.js`、`eln-results.js`、`eln-workspace.js` 和 `eln.css`。检查 `node --test scripts/eln.test.mjs` 覆盖演示计算、草稿不交付、失败修订、错批/权限、CSV、版本与附件身份保护。浏览器核对 83→92.22%、失败修订历史、切批草稿、只读、SOP定位与 CSV 取消/纳入流程。
