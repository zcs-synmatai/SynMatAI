# 产品需求文档

## 产品目标

- 将材料研发方案组织为可查看、可调整、可交付的项目流程。
- 在同一工作区连接人员、Agent、任务、文件、实验和计算模拟。
- 完成“新建项目→需求确认→调研→立项→SOP确认→研发→反馈与后续规划”的材料研发流程化。

## 用户角色

| 用户 | 典型任务 |
| --- | --- |
| 项目/研发负责人 | 确认需求和方案、安排工作、复核结果、管理成员与后续规划 |
| 研发成员 | 调研、整理文档、讨论方案、完成TODO与交付 |
| 实验操作人员 | 登记制备、批次、样板和异常 |
| 测试人员 | 提交测量、补充缺项、追加修订 |
| 管理 |  待定|

角色与身份切换仅用于前端演示，不代表正式权限控制。

## 完整业务流程

| 顺序 | 用户操作 | 系统反馈与推进条件 |
| --- | --- | --- |
| 进入项目列表 | 打开产品或返回列表 | 首次无指定页面时展示列表；保留内置示例与本机项目 |
| 新建项目 | 填项目名称、负责人、可选简介 | 创建独立项目，进入需求确认工作台；研发、量产保持待规划 |
| 补充基础信息 | 在对话中描述需求、约束、预期产出 | 生成《项目基础信息.md》草稿；明确确认并同意启动后，完成需求确认、进入技术调研 |
| 技术调研 | 分别确认两项并行TODO | “梳理技术路线与证据缺口”“形成技术调研报告”同时启动；全部完成后进入项目立项 |
| 项目立项 | 完成“立项材料准备” | 完成工作包并进入SOP审批；不新增“组织立项审批”默认任务 |
| SOP审批 | 确认“SOP项目工作流” | 本地记录确认，生成首个研发阶段；同时启动全部就绪根工作包 |
| 研发 | 按依赖执行工作包、任务，交付文档及实验记录 | 展示条件验证、路线比较、因子筛选、工艺优化、长期确认、客户准入；保留原型既有节点名称 |
| 客户准入 | 收集用户反馈，完成阶段任务确认 | 保存反馈，标记“下一研发阶段待规划”；不自动创建第二阶段 |
| 后续研发规划 | 后续明确决定启动 | 当前不自动生成；启动入口与规则待确认 |
| 量产 | 查看阶段入口 | 新项目仅展示待规划占位；现有小试/中试/量产示例不作为新项目自动生成规则 |

## 工作流模块
工作流管理模块需要提供CLI，提供Agent友好的设计能力。以便于SuperAgent管理和规划项目的工作流程，并按流程推进项目。
工作流中节点需要关联较多信息，除了工作流基础信息外，需要可关联任务，这样工作流才可以是任务的

| 规则 | 确定要求 |
| --- | --- |
| 基础的工作流管理 | 每项目对应一个工作流，有流程、节点以及节点之间连续关联。 
层级 | 项目→阶段→可选子阶段→工作包→任务；项目阶段当前不可编辑分为：立项、研发、和量产三个阶段，其中在研发阶段会根据项目的SOP拆分为子阶段。实际项目中研发可能是一个循环，所以根据项目在一个研发阶段完成后有可能启动研发2阶段。|
| 编号规则 | 阶段P1/R1/L1；子阶段R1S2；工作包P1T3或R1S2T1；TODO-001，完整引用P1T3-TODO-001。当已生成的节点删除的时候，不影响其他节点的编号。节点完整编号在项目中是唯一的。名称变化不改编号；同父级按最大序号递增，不复用删除编号；T11等旧示例编号兼容 |
|  |
| 三层画布 | 全局：阶段及子阶段；阶段：工作包；任务：工作包内部任务与文件 |
| 节点类型 | 快速创建/编辑使用结果文件、实验节点、模拟计算、分析节点、调研节点、临时任务；    |
| 文件节点 | 仅表达资料传递，无执行状态、负责人和执行Agent；来源由产出任务确定；不得手改文件来源或向只读输入写产出。 |
| 状态 | 工作包/阶段：待开始、进行中、已完成；任务：未开始、进行中、受阻、已完成；实验单独使用五态，不强行互转 |
| 依赖 | 真实执行依赖采用全部前置完成规则；穿透输入/结果文件，检查上游真实任务；上下文引用不算执行依赖 |
| 连线校验 | 拒绝自连、重复、循环及阶段内编辑器的跨子阶段连线；虚拟输入只发起、输出只接收。跨阶段的引用文件通过编辑输入与输出文件实现，或者对话中可以直接引用项目全局文件。 |
| 并行启动 | 工作包激活时，所有无未完成前置的任务同时启动；完成节点后，同时启动全部就绪下游，工作台仅展示其中一项 |
| 跨阶段 | 保留前序子阶段完成条件；SOP确认才生成研发内容；导航与画布建议线不改变业务状态 |
| 聚合完成 | 全部执行任务完成→工作包完成；全部工作包完成→所属子阶段/阶段完成；文件、临时对话不计执行进度 |
| 交付与完成 | 交付要求与实际文件分开；缺关联文件需提示，但原型允许人工明确确认工作完成，不补造文件或实验通过 |
| 已完成保护 | 内容、负责人、删除及既有依赖只读；允许作为新下游连线起点，不接收新上游；上传/登记产物和对话仍可用 |
| 新建与删除 | 新工作包仅一个默认任务；删除未完成任务清理连线，不删既有文件；移出实验节点保留ELN；删除不自动重接依赖 |
| 视图一致 | 画布、工作台、对话导航使用同一工作包/任务身份；选择、缩放、切层和浏览不改完成状态 |

## 任务管理

任务与画布的节点是两套呈现口径，背后是同一份数据。任务模块可以和工作流模块进行解耦，工作流侧重管理节点之间关联关系和推进流程，任务节点侧重在一个任务本身有哪些状态以及关联的东西有哪些。
任务管理的其他能力包括：任务的创建、修改、查询与筛选、分派负责与协作人、任务状态、优先级、截止时间、计划时间、依赖、交付要求等。
另外任务还需要关联到工作流节点、需要关联worker Agent、关联对话、关联产出文件、关联实验和ELN、关联模拟计算任务等内容。
根据任务类型需要确定默认AI完成还是人工完成。
任务管理模块需要提供CLI，提供Agent友好的设计能力。以便于Agent直接完成和管理任务的工作状态。

| 任务类型 | 执行方式 | 默认/现有Agent | 右侧工作区 | 交付物 |
| --- | --- | --- | --- | --- |
| 调研 | AI初稿人工审核 | 调研/技术调研Agent；文献类可用文献调研Agent | 对话资产、报告文档 | 调研报告、证据线索 |
| 文档整理 | AI初稿人工审核 | 资料整理Agent；具体任务可另指定 | 文档预览与草稿 | Markdown等文档 |
| 计算模拟 | 模拟执行 | 模拟计算Agent | 模拟工作台 | 演示结果、计算报告 |
| 实验 | 人工 | 实验Copilot辅助，不代替执行人 | 已关联实验ELN | 制备、批次、样板及异常记录 |
| 测试 | 人工 | 无全局固定Agent，沿用任务配置 | 已登记测量在ELN；整理工作看文档/资产 | 测量记录、报告 |
| 自定义 | 按任务配置 | 无统一默认，需指定负责人 | 默认对话与资产；明确关联后打开专用区 | 配置的交付要求及实际文件 |

## Agent能力

以下为产品需建设的Agent职责与能力。采用“Supervisor协调＋Worker执行”；初期同一Worker可复用多项Skill，按实际需要拆分独立Agent。

### Agent分工

| Agent | 优先级 | 使用场景 | 核心能力 | 主要产出与边界 |
| --- | --- | --- | --- | --- |
| Supervisor Agent | P0 | 项目流程；阶段、工作包层级的协调 | 完善项目目标；将已确认SOP拆为工作流；规划及调整工作包、任务、依赖、人员与交付；调用工作流/任务CLI；按依赖委派Worker、等待人工、接收交付；汇总进度与风险 | 流程草稿、任务安排、进度卡片；流程变更确认后生效，不绕过前置条件或人工确认；上下文组织。 |
| 技术调研Agent | P0 | 技术调研、研发中的证据补充 | 根据目标检索文献、专利与已有资料；比较技术路线；整理依据、适用范围和证据缺口；结合用户反馈修订报告 | 调研报告、来源清单、待验证问题；不把文献结论写成本项目实测结果 |
| 资料整理Agent | P0 | 基础资料、立项材料、SOP文档、阶段交付 | 读取指定资料及版本；提取要求；整理文档、记录模板和交付清单；按反馈修改文件；核对引用和缺项 | 文档草稿、差异说明、交付文件；SOP专业内容依赖已有方案或专用Skill，不凭空补专业条件 |
| 数据分析Agent | P0 | 实验、测试与计算结果回传后 | 核对批次、版本和数据完整性；调用分析Skill整理比较结果；对照已确认目标识别偏差；提出下一轮优化实验建议并与用户讨论 | 分析报告、异常与缺项、下一轮建议；专业分析方法需明确，优化建议经研发人员确认后交Supervisor调整流程 |
| 实验协作Agent | P0 | 实验与测试工作台、ELN | 解释已确认方案；提示准备事项和记录缺口；关联批次、样板、测量与文件；辅助整理异常及结果摘要 | 记录草稿、缺项提示、实验摘要；实验与测试由人执行，不编造实测值、不代提交或放行 |
| 模拟计算Agent | 待定 | 计算模拟任务 | 整理计算输入、辅助模型及参数配置、调用计算工具、跟踪运行、解释结果与异常 | 配置草稿、计算记录与报告；能力范围及Forgge2.0整合方式待确认，当前仅演示
|
| DOE实验设计Agent | 后续 | 专业实验设计任务 | 在专业能力可用后，结合目标、已有结果和约束，与研发人员共同设计实验及修订方案 | 待确认的实验设计方案；当前能力未具备，不纳入近期实现承诺或POC验收，也不替代人工实验执行 |

文献调研、证据核查、配方账本检查、文档生成、数据处理、进度汇报优先作为Skill复用，不因增加一项能力就新增Agent。

### 通用协作能力

| 能力 | 产品要求 |
| --- | --- |
| 对话入口 | 工作流主要与Supervisor讨论安排；工作台主要与当前任务Worker直接协作，不要求每轮经Supervisor转述 |
| 任务交接 | Supervisor识别具体任务意图后，交接至对应Worker；传递项目/节点、目标、约束、文件版本、已确认决定及未决问题；Worker交付后回报项目层 |
| 持续协作 | 同一任务可持续追问和修订；切换或恢复对话后保留既有约束与当前产物，不静默丢失历史决定 |
| 主动执行与确认 | 对已授权且输入齐备的AI工作先执行、再提交产物；需要人工处理时明确等待；生成初稿不自动完成整个人机协作任务 |
| 工具与Skill | 根据任务选择已有能力，通过CLI操作流程与任务；只引用真实执行结果，工具不可用或失败时说明原因，不伪装成功 |
| 状态反馈 | 展示处理中、待输入、待确认、失败和已交付；说明当前动作、缺项及下一步，长任务持续反馈进度 |
| 文件与版本 | 产物保存为可打开的文件资产，关联来源任务及输入版本；交付下游使用确定版本，新草稿不自动替换已采用版本 |
| 编辑边界 | 每个任务指定主Agent维护核心产物；用户另建讨论默认不修改核心文件，明确指定文件后才编辑，合入正式产物需核对版本 |
| 调度与恢复 | 按工作流启动所有就绪分支；失败不错误推进，重试不重复建任务或交付；旧任务、旧版本返回不得混入当前结果 |
| 能力边界 | 当前原型只演示角色、对话和产物；真实AI、Skill、CLI及handoff需后续接入与验证 |
